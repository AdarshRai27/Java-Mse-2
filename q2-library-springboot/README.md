# Q2 - Library Management REST API (Spring Boot)

A small REST API for a college library. Books are stored **in memory** in a
`Map<Integer, Book>`; there is no database.

- Java 17
- Spring Boot 3.5.7
- Maven
- Package: `com.college.library`
- Default port: `8080`

## Run the application

```bash
mvn spring-boot:run
```

The application seeds three books on startup, so this works immediately:

```bash
curl http://localhost:8080/api/books
```

Build and test:

```bash
mvn test
```

Run the packaged jar instead:

```bash
mvn -q package
java -jar target/library-api-1.0.0.jar
```

Storage is in memory: stopping the application resets all books to the three
seed records. IDs are generated by an `AtomicInteger` and are not reused.

## Endpoints

Base path: `/api/books`

| Method | Path | Success | Failure cases |
|--------|------|---------|---------------|
| `POST` | `/api/books` | `201 Created` + saved book + `Location` header | `400 Bad Request` for blank title/author, missing or negative `availableCopies` |
| `GET` | `/api/books` | `200 OK` + JSON array (empty array if none) | - |
| `GET` | `/api/books/{id}` | `200 OK` + book | `404 Not Found` if the id does not exist |
| `PUT` | `/api/books/{id}` | `200 OK` + updated book | `404` if id missing; `400` for invalid data |
| `DELETE` | `/api/books/{id}` | `204 No Content` | `404 Not Found` if the id does not exist |

Error responses are JSON:

```json
{"error":"Book with id 5 not found"}
```

```json
{"error":"Title must not be blank"}
```

`POST` ignores any `id` sent by the client and always assigns the next id.
`PUT` never changes the id; it updates only title, author, category, and
availableCopies.

## curl examples

### Create a book - 201

```bash
curl -i -X POST http://localhost:8080/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"Design Patterns","author":"Erich Gamma","category":"Programming","availableCopies":3}'
```

### List all books - 200

```bash
curl -i http://localhost:8080/api/books
```

### Get one book - 200

```bash
curl -i http://localhost:8080/api/books/1
```

### Get a missing book - 404

```bash
curl -i http://localhost:8080/api/books/9999
```

### Update a book - 200

```bash
curl -i -X PUT http://localhost:8080/api/books/2 \
  -H "Content-Type: application/json" \
  -d '{"title":"The Alchemist (Updated)","author":"Paulo Coelho","category":"Fiction","availableCopies":10}'
```

### Update a missing book - 404

```bash
curl -i -X PUT http://localhost:8080/api/books/9999 \
  -H "Content-Type: application/json" \
  -d '{"title":"Ghost Book","author":"Nobody","category":"Fiction","availableCopies":1}'
```

### Create with invalid data - 400

```bash
curl -i -X POST http://localhost:8080/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"   ","author":"Some Author","category":"Fiction","availableCopies":2}'
```

```bash
curl -i -X POST http://localhost:8080/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"Bad Copies","author":"Some Author","category":"Fiction","availableCopies":-2}'
```

### Update with invalid data - 400

```bash
curl -i -X PUT http://localhost:8080/api/books/2 \
  -H "Content-Type: application/json" \
  -d '{"title":"Valid Title","author":"   ","category":"Fiction","availableCopies":1}'
```

### Delete a book - 204

```bash
curl -i -X DELETE http://localhost:8080/api/books/3
```

### Delete a missing book - 404

```bash
curl -i -X DELETE http://localhost:8080/api/books/9999
```

On PowerShell, `curl` may be an alias for `Invoke-WebRequest`. Use `curl.exe`
for the commands above, and be careful with JSON quoting. Git Bash works as-is.

## Automated tests

### MockMvc tests

```bash
mvn test
```

`BookControllerTest` covers:

- list, create, get, update, delete happy paths
- 404 for get, update, and delete of a missing id
- 400 for blank title, blank author, and negative copies

### End-to-end curl script

Start the application in one terminal:

```bash
mvn spring-boot:run
```

In another terminal, from this folder:

```bash
bash test-api.sh
```

On Windows, run the script with Git Bash:

```powershell
& "C:\Program Files\Git\bin\bash.exe" test-api.sh
```

The script creates its own book, exercises all endpoints and failure cases,
deletes the book, and exits with code `1` if any status code is unexpected.
It can be run repeatedly.

Expected final line:

```text
All API checks passed.
```

## Design notes

- `Map<Integer, Book>` is a `LinkedHashMap`: O(1) average lookup by id, and
  insertion order is kept for `GET /api/books`.
- An `AtomicInteger` generates ids without scanning the map.
- Service methods are `synchronized`, so concurrent requests cannot corrupt the
  map. In a real multi-instance deployment, a database and transactions would
  replace this in-memory approach.
- The controller only maps HTTP to service calls and status codes. Validation
  and storage are in `BookService`, which keeps the controller thin.
- Validation is written by hand in the service, so the project does not need the
  optional `spring-boot-starter-validation` dependency.

## Assumptions

- `category` is optional; title and author must not be blank.
- `availableCopies` is required and must be `>= 0`.
- Duplicate titles/authors are allowed; only the generated `id` identifies a
  book.
- Data is intentionally not persisted between restarts, as required by the
  assignment.
